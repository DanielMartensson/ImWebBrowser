1. Overview

ImWebBrowser is a minimal GPU-accelerated web browser that renders web content via WPE WebKit and displays it using Dear ImGui on an SDL3 window. It supports two rendering backends: OpenGL ES 3.1 (default, for embedded targets like STM32MP257F) and Vulkan (for desktop GPUs with dmabuf support).

Key design principles:

  • Zero-copy GPU frame path — web frames never touch the CPU (except SHM fallback)
  • Single-process — no IPC overhead between browser and renderer threads
  • Embedded-first — GLES 3.1 target (VeriSilicon GC7000), runs on aarch64 Cortex-A35
  • ~4,500 lines of first-party code across 24 source files

Inheritance

Both renderers use multiple inheritance: they implement Renderer (for Application) and FrameSink (for WebPage):

Renderer (abstract)          FrameSink (abstract)
    |                            |
    +-- GlRenderer (also: FrameSink)
    +-- VulkanRenderer (also: FrameSink)

The renderer's frame_sink() method returns *this, so the same object is used for both rendering and frame reception.

6. Frame Loop

File: src/application/application.cpp:259 — Application::run()

while (m_running) {
    // 1. SDL events
    while (SDL_PollEvent(&event)) {
        ImGui_ImplSDL3_ProcessEvent(&event);  // feed ImGui
        handle_event(event);                  // shortcuts + input
    }

    // 2. Begin ImGui frame (makes GL context current)
    m_renderer->begin_frame();

    // 3. Pump WPE/GLib main loop (new frames arrive via callbacks)
    m_browser.wpe().pump_main_context();

    // 4. Build web view texture handle
    texture.handle = m_renderer->webview_texture();
    texture.valid = m_renderer->frame_ready();

    // 5. Draw UI (toolbar + web view quad, reports viewport to WPE)
    m_ui.draw(m_browser, texture);

    // 6. Update coordinate mapping for the reported viewport
    m_input.set_view_geometry(viewport.x, viewport.y, ...);

    // 7. Render ImGui draw data + swap/present
    m_renderer->render_present();
}

When minimized, the loop sleeps 16ms per frame to avoid spinning (application.cpp:310).

GPU compat: GLES 3.1 (VeriSilicon GC7000 compatible). Uses glBlitFramebuffer instead of glCopyImageSubData (which requires ES 3.2).

Frame Processing Pipeline (on_egl_image)

File: gl_renderer.cpp:216

  1. Wait for previous frame's glFenceSync (non-blocking, line 226)
  2. Bind EGL image to scratch texture via glEGLImageTargetTexture2DOES (line 233)
  3. Query internal format, ensure owned texture matches (line 244)
  4. GPU-only blit: glBlitFramebuffer scratch → owned texture (line 257)
  5. Place fence for next frame (glFenceSync, line 268) — returns to WPE immediately

SHM Fallback (on_shm)

File: gl_renderer.cpp:287

When GPU renderer isn't available, WPE falls back to shared memory. Pixels are copied from BGRA to RGBA byte order and uploaded row-by-row via glTexSubImage2D. The first SHM frame is dumped to /tmp/opencode/shmdump.bgra for debugging.

Frame Pacing

After each exported frame, the host must call wpe_view_backend_exportable_fdo_dispatch_frame_complete() (or the EGL/SHM variant) to unblock WPE from rendering the next frame. Without this, WPE blocks after the first frame.

In the GL backend, glFenceSync allows returning to WPE immediately while the GPU copy is in-flight.

Dead Key Compose

File: src/input/xkb_layout.cpp:167

The XkbLayout manages a xkb_compose_state for dead key sequences (Swedish: ä, ö, å, etc.). When a key produces a keysym in the COMPOSING state, it is buffered. The next key completes the compose: COMPOSED → emit composed character; CANCELLED → emit dead key's own character + the current key.

The locale is read from the LANG environment variable (required, xkb_compose_table_new_from_locale() crashes with NULL).

Mouse Pipeline

File: src/input/input_translator.cpp:124

Motion: logical window coords → device-pixel coords relative to web view viewport (line 124-143). Buttons: SDL button IDs → WPE convention (Left=1, Right=3, Middle=2, X1=4, X2=5). Events outside the web view rectangle are silently dropped.

Scroll

File: src/input/input_translator.cpp:185

Not Implemented

Touch input (no SDL_EVENT_FINGER_* processing) and gamepad/controller input are not supported.

13. Security

Sandbox

Disabled unconditionally at runtime (wpe_module.cpp:34): WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS=1. This allows the WebProcess to access /dev/dri directly for GPU rendering. Without this, Mesa falls back to Vulkan/Zink inside the sandbox on Intel.

Permissions

All permission requests (camera, microphone) are granted unconditionally (web_page.cpp:351).

Window Creation

All window.open() requests are rejected (web_page.cpp:377) — no new windows/tabs.

Crash Recovery

Web process crashes trigger an automatic page reload (web_page.cpp:365).
